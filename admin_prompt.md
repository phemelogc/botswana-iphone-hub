# Prompt to Generate Brooklyn's Phone Shop Admin Dashboard

You can copy and paste the entire prompt below into any AI code generator (e.g., v0, Lovable, Cursor, Bolt, or ChatGPT) to build the administration portal for Brooklyn's phone shop.

***

```text
Act as a senior frontend engineer. Build a responsive Admin Inventory Dashboard for Brooklyn's phone shop "B Phones". This portal will be used by Brooklyn on both his computer and his phone to manage inventory in real time.

### 1. Project Stack & Layout
- Framework: React + Vite + Tailwind CSS (TypeScript preferred).
- Responsive Design: Desktop view must use structured tables/lists with sticky headers, while Mobile view must adapt into intuitive, large tap-target grid cards (Brooklyn needs to edit items quickly on his phone).
- Color Scheme: Modern, premium dark mode by default (Obsidian dark background, zinc cards, amber/gold accents) to match the customer-facing site, but clean and highly readable.

### 2. Firestore Database Connection
The application must connect to Google Cloud Firestore.
It must initialize Firebase and read/write to a collection named: "phones".

The Firestore configuration should be editable via a configuration panel or loaded from standard environment variables:
- apiKey
- authDomain
- projectId
- storageBucket
- messagingSenderId
- appId

### 3. Data Schema
Every document in the Firestore "phones" collection follows this structure:

interface Phone {
  id?: string;            // Document ID auto-generated by Firestore
  model: string;          // e.g., "iPhone 15 Pro Max"
  type: "preowned" | "brandnew";
  
  // Pre-Owned Fields (Conditional)
  priceRange?: string;    // e.g., "P9500-P11000"
  condition?: string;     // e.g., "Varies", "Like New", "Excellent"
  
  // Brand New Fields (Conditional)
  storage?: string;       // e.g., "128GB", "256GB"
  warranty?: string;      // e.g., "1 Year", "6 Months"
  price?: string;         // e.g., "P15200"
  
  // Website Sales / Promo Fields
  isSale?: boolean;        // Boolean flag for Website Special Deals
  originalPrice?: string;  // e.g., "P11000" (original retail price)
  salePrice?: string;      // e.g., "P9900" (discounted retail price)
  saleDescription?: string;// e.g., "Save P1100 + Free cover + glass protector"
  
  createdAt: any;         // Firestore Server Timestamp (for sorting)
}

### 4. Core Features Required

#### A. Real-time Inventory List
- Display all devices in a clean list or grid.
- Sort items by `createdAt` (descending) by default.
- Filter inventory tabs: [ All Devices ], [ Pre-Owned ], [ Brand New ], [ Active Sales 🔥 ].
- Search bar to filter by phone model (e.g., typing "14 Pro").

#### B. Conditional Add / Edit Form Modal
A form to Add or Edit a device. The form fields must dynamically change based on selection:
1. "Device Type" selector: [ Pre-Owned ] or [ Brand New ]
2. If "Pre-Owned" is selected:
   - Show: Model Input (text), Condition Input (dropdown or text, default: "Varies"), Price Range Input (text, e.g., "P3000-P3500").
3. If "Brand New" is selected:
   - Show: Model Input (text), Storage Input (dropdown: 64GB, 128GB, 256GB, 512GB, 1TB), Warranty Input (text, default: "1 Year"), Price Input (text, e.g., "P6700").
4. "Put this device on Special Sale?" toggle (`isSale`):
   - When toggled ON, display:
     - Original Price Input (text, e.g., "P7000" - crossed out on site).
     - Sale Price Input (text, e.g., "P6300" - active selling price).
     - Sale Description Input (text, e.g., "Free cover & delivery").
   - When toggled OFF, clear these sale fields from the Firestore document object.

#### C. Write Actions
- Add Device: Save to Firestore collection "phones", setting `createdAt` to serverTimestamp().
- Edit Device: Update existing Firestore document values.
- Delete Device: Remove the document from Firestore. Include a "Confirm Delete" modal warning Brooklyn before removing the item.

#### D. User Experience (UX) Enhancements
- Display active toast notifications (success/error/info) upon adding, updating, or deleting.
- Disable submission buttons during loading states.
- Clean validations (prevent saving empty models or formats that don't match, e.g. warn if price lacks "P" prefix or storage is empty).
```
